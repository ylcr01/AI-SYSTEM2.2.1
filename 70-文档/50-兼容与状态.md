# 兼容与状态

新任务和当前运行记录使用 Task Schema V10。V6/V7/V8/V9 活动记录读取时做保守的内存兼容，不自动改写；V8 以前没有完整结果指标，V10 以前没有对话闭环事实，读取时分别以 `trackingStartedAt=null` 和 `conversationOutcome=null` 明确标识，不把未知样本纳入对应比率。更早记录由对应历史版本读取。

非终态记录按用途分层：写作态位于 `80-运行记录/进行中`，`waiting_acceptance` 位于 `80-运行记录/待验收`，终态追加到 `历史.jsonl`。`task.mjs 诊断状态` 始终只读；`task.mjs 迁移状态` 默认也只返回 dry-run 计划，只有显式 `--apply` 才把受支持的 V6/V7/V8/V9 非终态记录固化为 V10 并修正目录错位。写入前原样备份到 `迁移备份/<migrationId>/`，重复 Task、无效记录、终态错放或目标冲突会使迁移 fail closed；迁移不推断 accepted、closed、cancelled 或任何用户决定，也不自动处理历史账本。

测试入口为每次运行创建独立临时 `stateRoot`，不会把测试 Task 写入中央运行账本。需要显式覆盖时可设置 `AI_RD_OS_STATE_ROOT`。

当前版本为 `runnable-baseline`，不是 `stable`。文档中的未实现计划不得描述成当前能力。

默认 Task 回执把内部状态压缩为 `working`、`needs_decision`、`delivered` 和 `done` 四种用户状态；`--full` 继续返回内部状态、Alignment、Change Rationale、Verification、Conversation Outcome 和 Outcome Metrics，供宿主与维护者诊断。`accepted` 与 `closed` 都映射为 `done`，但内部语义和指标保持分离。

成功交付生成本轮唯一的 `deliveryId`；再次交付会轮换该标识，旧标识拒绝写入。`后续` 命令必须同时提供精确 `taskId`、`deliveryId`、幂等 `observationId` 和封闭的 `kind`，不会扫描任务、保存消息正文、运行工程检查或自动创建范围扩展 Task。
