# 兼容与状态

新任务和当前运行记录使用 Task Schema V10，结果指标子结构使用 Schema 2。V6/V7/V8/V9 活动记录读取时做保守的内存兼容，不自动改写；V8 以前没有完整结果指标，V10 以前没有对话闭环事实，旧指标缺少真实检查执行次数/耗时时记为 `legacyVerification`，不用交付墙钟时间反向填充。未知事实保持 null/legacy，更早记录由对应历史版本读取。

非终态记录按用途分层：写作态位于 `80-运行记录/进行中`，其中 `ready_to_integrate` 仍持有源 Worktree 写占用；`waiting_acceptance` 位于 `80-运行记录/待验收`，终态追加到 `历史.jsonl`。`task.mjs 诊断状态` 始终只读，并分开返回 `storageIntegrity` 与 `acceptanceEligibility`；前者失败时后者明确跳过，不伪装为一个成功结果。`task.mjs 迁移状态` 默认也只返回 dry-run 计划，只有显式 `--apply` 才把受支持的 V6/V7/V8/V9 非终态记录固化为 V10 并修正目录错位。写入前原样备份到 `迁移备份/<migrationId>/`，冲突 fail closed；迁移不推断用户决定或处理历史账本。

未显式传入 `stateRoot` 时，状态根按 `AI_RD_OS_STATE_ROOT` → `AI_RD_OS_ROOT/80-运行记录` → 当前脚本所属系统根的顺序确定。这样从任务 Worktree 调用其脚本时仍读写中央运行账本，不会在每个 Worktree 中形成互相不可见的 Task 状态副本。测试入口为每次运行创建独立临时 `stateRoot`，不会把测试 Task 写入中央运行账本；需要显式覆盖时设置 `AI_RD_OS_STATE_ROOT`。

Task 列表和评估默认以 `gitCommonDir` 识别逻辑项目，因此同一仓库的 Local 与 linked Worktree 归为同一样本域；工作树写锁仍按 `gitRoot` 隔离。新 Task 保存 `evaluationContext`：系统版本/Commit/脏状态和 Node/平台/架构自动捕获，模型、推理强度和执行环境只保存宿主显式传入的低敏感标签。旧 Task 缺少这些字段时保持 unknown，不用当前环境反向补全。

当前版本为 `runnable-baseline`，不是 `stable`。文档中的未实现计划不得描述成当前能力。

默认 Task 回执把内部状态压缩为 `working`、`needs_decision`、`delivered` 和 `done` 四种用户状态；`--full` 继续返回内部状态、Alignment、Change Rationale、Verification、Conversation Outcome 和 Outcome Metrics，供宿主与维护者诊断。`accepted` 与 `closed` 都映射为 `done`，但内部语义和指标保持分离。

成功交付生成本轮唯一的 `deliveryId`；再次交付会轮换该标识，旧标识拒绝写入。`后续` 命令必须同时提供精确 `taskId`、`deliveryId`、幂等 `observationId` 和封闭的 `kind`，不会扫描任务、保存消息正文、运行工程检查或自动创建范围扩展 Task。

用户退回或 `defect-return` 先落账并使上轮 Evidence、Review、Handoff、Rationale 和 Check Manifest 立即失效，输入周期递增。已集成任务先进入 `blocked` 再安全恢复专属返工 Worktree；恢复失败保留退回事实、Blocker 和诊断，`恢复`可重试。如果 ChangeSet 未变且 Goal 未重新对齐，再交付失败关闭。集成验证预算耗尽时仍保持 `ready_to_integrate`；显式有界续期只恢复集成资格，不转成返工或已交付。

Browser 运行器已实施 4 条 flow、单条 15 秒、整批 120 秒、外层 180 秒与首败熔断。同步 Runner 目前无法在子进程期间监督 30 秒心跳/无有效输出终止，回执以 `unimplemented` 明确保留此缺口；文档或规则不能代替执行能力。
