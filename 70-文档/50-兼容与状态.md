# 兼容与状态

新任务和当前运行记录使用 Task Schema V9。V6/V7/V8 活动记录读取时做保守的内存兼容，不自动改写；V8 以前没有完整结果指标，读取时以 `trackingStartedAt=null` 明确标识，不进入首轮验收率、返工和耗时统计。更早记录由对应历史版本读取。

非终态记录按用途分层：写作态位于 `80-运行记录/进行中`，`waiting_acceptance` 位于 `80-运行记录/待验收`，终态追加到 `历史.jsonl`。旧版遗留在“进行中”的待验收记录仍可读取，下一次合法状态更新时才移动。`task.mjs 诊断状态` 只读报告重复、错位和无效记录，不自动修复或迁移。

测试入口为每次运行创建独立临时 `stateRoot`，不会把测试 Task 写入中央运行账本。需要显式覆盖时可设置 `AI_RD_OS_STATE_ROOT`。

当前版本为 `runnable-baseline`，不是 `stable`。文档中的未实现计划不得描述成当前能力。

默认 Task 回执把内部状态压缩为 `working`、`needs_decision`、`ready_for_acceptance` 和 `done` 四种用户状态；`--full` 继续返回内部状态、Alignment、Change Rationale、Verification 和 Outcome Metrics，供宿主与维护者诊断。
