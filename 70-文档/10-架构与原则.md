# V2.2.1 架构与原则

系统由执行可信内核、按需工程质量内核和可选的项目业务工作站层组成。模型位于这些约束与事实之间，自主求解问题。

```text
项目事实 + Manifest + 最小质量参照
                ↓
          强模型自主求解
                ↓
       当前 ChangeSet 与 Evidence
                ↓
 Scope / Evidence / Review / 规格一致性 / 用户验收
```

执行可信内核只硬控确定性事实。工程质量内核只在 structural 任务加载，不规定模型思考过程。详细规格追踪只在项目配置映射或明确声明规格影响时启用，Review Package 只在显式审查路径生成。项目可显式绑定外部整项目底座；底座只按任务相关性读取入口、质量清单、检查清单和最多两份资料，不复制源码。

项目业务工作站采用“中央控制层 + 项目实例层”：中央仅保存通用 Skill、Contract、模板和命令，项目 `.ai/workstations/` 保存领域索引和稳定业务知识。工作站是软领域归属；用户可以直接派发任务，当前工作站可自治实现并按需启用临时子 Agent。上下文最多自动选择一个领域，Worktree 只按并行写任务临时分配，现有 Task、Evidence、单一集成者和用户验收门禁保持不变。
