# V2.3.0 架构与原则

系统由执行可信内核和按需工程质量内核组成。模型位于这些约束与事实之间，自主求解问题。

```text
项目事实 + Manifest + 最小质量参照
                ↓
          强模型自主求解
                ↓
       当前 ChangeSet 与 Evidence
                ↓
 Scope / Evidence / Review / 规格一致性 / 用户验收
```

执行可信内核只硬控确定性事实。工程质量内核通过 Quality Profile 路由 Contract 和 Canonical；Profile 是系统内部选择配置，不是宿主 Skill，也不规定模型思考过程。自动路由只在 structural 任务加载主要 Contract/Canonical，显式 `--quality-profile` 可为局部任务请求一个 Contract。详细规格追踪只在项目配置映射或明确声明规格影响时启用，Review Package 只在显式审查路径生成。项目可显式绑定外部整项目底座；底座只按任务相关性读取入口、质量清单、检查清单和最多两份资料，不复制源码。

V2.3.0 将内部 Task 状态压缩为四种默认用户状态，并把 Alignment、Change Rationale、Task Check、指纹和门禁细节留在 `--full` 宿主视图。Task Schema V10 只记录可由状态事件和精确 continuation 确认的结果事实，不保存用户消息正文，也不根据模型自评生成质量分数。

“本轮已交付”“对话已收口”和“用户已验收”是三个不同事实：`waiting_acceptance` 对外映射为 `delivered`；相关询问保持已交付，缺陷退回进入返工；范围扩展、非正式肯定或话题推进可以形成 `closed`；只有用户明确通过才能形成 `accepted`。后续分类只做常数时间状态写入，不触发工程重验或自动创建新 Task。
