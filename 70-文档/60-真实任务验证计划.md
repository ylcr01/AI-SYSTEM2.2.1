# 真实任务验证计划

稳定发布前执行 20～30 个真实任务，覆盖 Quick、Standard、Controlled、Local、Structural、Browser/No Browser、项目 Canonical、规格一致性、Decision、整项目底座、Experience Candidate、跨模型 Handoff 和用户退回。

## 核心指标：First-pass Acceptance Rate

最重要指标是用户第一次收到交付后、不要求返工直接通过的比例。它是目标理解、实现正确性、代码质量、改动范围与验证有效性的综合结果。

## 每个真实任务的记录维度

### 效率

- 总耗时
- 用户确认次数
- 无效读取文件数
- 验证耗时
- 失败检查次数

开始可以人工简记，不要求完美自动采集。

### 准确度

- 是否误解目标
- 是否遗漏 Acceptance
- 是否发生不必要 Scope 扩张

### 代码质量

只用三档记录：明显提升 / 无明显影响 / 明显下降。

抽样检查维度：

- 简洁
- 命名
- 结构
- 性能
- 架构一致
- 可维护性

不做 100 分制或伪精确评分。

### 业务结果

- 是否首轮验收
- 返工次数
- 用户退回原因
- Regression 数量
- 用户手工修正量

## 观察项

继续观察：目标误解、Scope、Evidence 缺口、Review 是否改变结论、Contract/Canonical 和整项目底座是否减少返工、规格门禁误报、经验候选复用价值、检查耗时、Handoff 接续和用户退回原因。

## 建议任务集

至少覆盖：

- E01 小 Bug Fix
- E02 普通 Feature
- E03 局部重构
- E04 性能优化
- E05 Web 交互
- E06 Server 事务/状态
- E07 权限任务
- E08 Reference Migration
- E09 Structural Change
- E10 Worktree 并行集成

## 记录方式

前 20～30 个真实任务只用 Markdown / JSON 简记。只有记录数量已经造成明显负担时，才评估独立汇总脚本；不建设自动 Agent Benchmark 平台。

## 规则演进门禁

只有同一能力出现两个以上经真实项目验证且适用条件不同的范式，才扩展中央样板数组。只有重复检查耗时成为可测量瓶颈，才重新评估成功缓存；只有经验数量增长到精确查重和人工复核明显不足，才评估相似度或评分机制。新机制必须由真实退回、返工、误解、质量下降或上下文浪费驱动，不根据文件数、测试数、阶段数或流程完整率自动调整规则。
