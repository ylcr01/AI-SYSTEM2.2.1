# 稳定内核减重与按需能力边界

## 背景

系统已经完成方案设计并准备接入真实项目。现有实现包含重复发布验证、生成物入库、单样板多级索引、默认 Review Package、成功检查缓存和尚未获得使用证据的经验评分，增加了维护与认知成本。

## 决定

- 保留项目身份、Scope、ChangeSet、Evidence、原子状态、用户验收、模板绑定、Handoff 和验证预算等可信执行内核。
- 发布清单改为按需生成，删除静态校验表、原始验证日志和人工加权保真度层。
- 能力 Contract 合并验证维度，中央样板统一在一个可扩展数组 Manifest 中登记。
- 规格追踪继续作为长期能力；无映射且 `specImpact=none` 时退出主路径，有映射或显式规格影响时自动启用。
- Experience Candidate 保留已验收来源、必填内容和精确查重，取消自动评分与模糊相似度。
- 取消成功检查缓存；保留总验证预算、检查超时和相同输入失败重试保护。
- Review Package 只在显式要求或实际提供 Review 时生成。

## 影响

- 真实项目可继续使用详细规格映射和 Decision 门禁。
- 中央样板新增由维护者人工确认与登记，运行时自动路由；添加数组项不需要修改加载器。
- 发布结果不再提供人工权重计算的“保真度百分比”，以系统自检、行为测试和用户验收表达真实性。
- 旧 Task Schema 由历史版本读取，不在当前内核迁移。

## 未改变

不改变注册表中的真实项目与模板身份，不读取或修改外部项目源码，不降低外部写入授权和用户最终验收边界。

## 验证

运行系统自检、全部测试、发布档验证，并通过当前 Task 的 ChangeSet、规格 Decision 和 Evidence 门禁。

## 回滚

如果真实任务数据证明某项已删除机制有显著净收益，从 Git 历史恢复为独立可选能力，不重新进入所有 Task 的默认路径。
