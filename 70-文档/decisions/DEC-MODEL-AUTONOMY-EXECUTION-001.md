# 普通研发任务恢复模型自主执行

## 背景

真实 POC 本地调试任务只需要在一个现有文件中修改约十行代码。系统却因 `src/api/pid.js` 路径命中 `public-contract` 风险模式，把普通修改升级成正式 Task；模型随后新增测试，触发 Scope 重建、两个 Worktree、重复验证和集成清理。第一次正式 Task 运行约 9 分钟后取消，第二次从准备到集成约 2 分 32 秒，而记录的正式检查执行仅 397 毫秒。用户明确退回该交付，认为流程降低模型判断能力、隐藏业务 Diff 并制造不相称成本。

现有按风险分级路由已经承认所有写入强制 Worktree 的固定成本，但仍让意图关键词、目录名、预先 Scope 和最终分类替模型决定普通任务的控制路径。该机制没有阻止不必要修改，只把错误判断变成更昂贵的流程失败。

## 决定

- 普通仓库修改由模型根据用户目标、代码、调用方和项目事实自主理解、探索、实施和选择验证；Context 只提供事实，不以关键词、目录名或文件类型自动升级流程。
- 普通修改不预建 Goal Card、Scope、Task、Evidence、结果记录或本地提交。完成后的 Git ChangeSet 是范围事实；只有用户明确限定文件时，Scope 才作为实施前硬边界。
- Worktree 只由工作区脏、真实占用、已知并发、状态无法确认或用户明确隔离要求触发，用于保护已有改动，不作为语义风险分类结果。
- 正式 Task 是持续跟踪、跨对话交接、并行隔离或已授权外部写入的显式能力。调用 `准备` 表示明确选择正式闭环；正式 Task 继续保留专属 Worktree、Scope、Evidence、提交和集成真实性门禁。
- 普通修改默认保持用户可见 Git Diff。只有用户明确要求提交、交接或结果记录时才提交；机器交换产物必须位于系统状态或临时目录，不得进入项目或用户更改列表。
- 外部/不可逆操作授权、用户已有改动保护、同工作树并发保护、Git 身份、状态真实性、如实验证和禁止自动 Push 保持硬约束。

## 影响与边界

本决定删除的是对模型语义判断的机械替代，不删除事实预检、项目上下文加载、Git Diff、相称验证、显式正式 Task 或高后果操作授权。结构、权限、安全、迁移等语义仍可帮助模型选择读取内容和验证方式，但不自动创建 Task 或 Worktree。

普通路径不再自动形成完成轮次样本；需要评估的任务可以由用户或模型显式选择正式 Task，或在用户要求提交后选择性记录轻量结果。不能为了指标完整强迫所有修改进入记录系统。

## 证据状态

本次用户退回和运行记录直接证明旧路径在该任务上的净收益为负；历史风险分级决定也记录了多个简单任务的等待、重复验证和控制面膨胀。用户已明确授权立即采用删除式调整。跨项目长期收益仍为方向性证据，不因本次技术测试通过而宣称稳定改善。

## 验证与停止条件

- 定点测试只证明普通意图、结构词、权限词和普通路径不再自动进入正式路由；显式 `tracked`、handoff、external-write 和真实工作树冲突仍能触发对应能力。
- 后续观察普通任务总耗时、用户可见 Diff、返工、遗漏和用户已有改动保护。若出现同工作树并发覆盖、用户改动丢失或外部写入绕过授权，立即停止扩大普通路径并修复对应事实门禁。
- 不得用重新增加关键词、Scope、Task 或重复测试作为默认回滚；只有可复现的事实边界缺口才允许最小恢复。
