# 以真实问题和净正向收益驱动系统演进

## 背景

AI-SYSTEM 的存在是为了解决强 Coding Agent 在真实研发中的目标误解、上下文错误、越界修改、错误证明、集成失真和重复返工，而不是建设更多流程。当前仓库已经具备轻量纠偏内核、真实任务验证计划和机制净收益评估，但最高使命、核心诉求以及中央机制新增、修改、精简和删除的统一准入规则尚未形成一个可确定路由的权威入口。

缺少这一入口时，后续模型可能把规则数量、技术自检或设计合理性误写成系统收益，也可能在单次问题后扩大中央机制，逐渐增加 Context、等待、验证和控制面成本，反过来压制模型能力。

## 决定

- 以 [`../10-架构与原则.md`](../10-架构与原则.md) 定义的系统使命和六项核心诉求作为中央演进目标：模型能力不降低，准确、高质量、高效率、优雅、清晰。
- 准确、安全、用户已有改动、权限、隐私、数据完整性和状态真实性属于不可用其他收益抵消的硬约束。
- 中央 Prompt、Context、Contract/Canonical、Task/Worktree、Evidence/Acceptance、Skill/Agent 和验证门禁的新增、修改、精简、删除与恢复，统一遵循 [`../55-系统演进准入.md`](../55-系统演进准入.md)。
- 候选方案可以记录，受控方案可以试验；只有真实结果表明至少一项核心诉求改善且硬约束没有实质退化，才可声明净正向并进入中央默认路径。
- 证据不足时使用 `observe` 或 `experiment`。普通项目局部修复和事实性文档纠错不承担中央机制评估成本；安全、权限、隐私和数据完整性事件允许快速升级。
- 使用真实对话、Git、实际验证、用户反馈、Decision 和按需评估记录支撑演进判断，不新增审批、评分、Dashboard 或持久化状态机。

## 核心诉求影响

| 维度 | 预期影响 | 当前证据状态 |
|---|---|---|
| 模型能力 | 明确禁止用规则替代合理判断，并限制中央机制扩张 | 设计约束，待真实任务观察 |
| 准确 | 机制变更必须关联真实问题、实现版本和结果证据 | 当前事实来源可承载，长期效果待观察 |
| 质量 | 防止技术自检、文档和流程完整度冒充真实交付质量 | 已有状态真实性原则支持，新增准入规则待验证 |
| 效率 | 优先项目局部和最小方案，阻止无证据的默认流程扩张 | 方向性判断，需记录准入本身的流程成本 |
| 优雅 | 复用现有机制，不增加新状态机和平台 | 本 ChangeSet 可直接验证 |
| 清晰 | 使命、权威事实、证据状态和变更决定统一入口 | 本 ChangeSet 可直接验证 |

本决定正式采纳“问题驱动和净正向准入”作为治理原则，但不宣称它已经改善长期交付指标。其运行效果保持 `experiment`，需通过后续真实任务评估是否 `keep`、`shrink` 或 `remove`。

## 负向成本与反证

- 每次中央机制变更增加一次影响分析；如果触发范围过宽，会使普通任务重新变重。
- 真实任务样本不足时无法稳定归因，可能导致有价值机制长期停留在观察状态。
- 文档可能陈旧，因此当前行为仍以代码、配置、Manifest、Git 状态和测试为准。
- 机制参与成功任务不等于机制导致成功；评估必须同时寻找反证和成本。

## 晋升与停止条件

- 后续真实任务中，中央机制变更能够减少无证据扩张、重复流程或状态失真，且没有增加显著返工、遗漏或等待成本时，保留并按需精简。
- 若普通 Quick 或项目局部修复被频繁误路由到正式评估，立即缩小触发范围。
- 若影响卡持续产生重复文字、没有改变决定或增加的流程成本超过可测收益，删除独立模板要求，只保留最少 Decision 字段。
- 若该规则压制模型获取真实源码、比较方案或处理明确任务，立即回退相关强制项。

## 回滚

删除 `AGENTS.md` 中的中央演进触发规则和 `README.md` 入口，归档准入文档与本 Decision；保留真实问题和评估事实，不删除历史证据。回滚不得同时恢复任何已经被独立证明为错误或不安全的旧机制。
