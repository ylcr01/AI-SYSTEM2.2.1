# 项目业务工作站采用中央控制层与项目实例层

## 背景

长期使用单条项目对话会累积日志、历史推断和过期架构信息；主 Agent 串行分派所有任务也会限制业务模块的并行维护。另一方面，把每个成员固定为永久子 Agent、分支或 Worktree，会把业务身份与临时执行资源错误绑定。

## 决定

- AI 研发操作系统保存通用的工作站 Skill、Contract、模板、初始化/检查命令和上下文路由。
- 目标项目在 `.ai/workstations/` 保存领域索引、共享规则、领域档案和运行手册；中央注册表不复制业务知识。
- 每个工作站是用户可直接进入的长期业务身份，可以独立分析、实现、验证和提交，也可以按需使用临时子 Agent。
- 领域采用软归属：提供默认专业范围和路由提示，不形成目录级写权限。
- 上下文渐进加载，最多自动选择一个领域；歧义时显式指定，不批量加载所有档案。
- 对话、分支、Worktree 和临时子 Agent 都按任务分配。并行写仍使用 detached worktree 和单一集成入口。
- 项目事实高于工作站档案；初始化必须基于用户确认的方案且不得覆盖现有工作站目录。

## 影响

- 多个业务成员可以由用户直接并行使用，长期知识不依赖单条对话。
- 领域局部性降低搜索噪声，但维护档案成为项目的持续成本。
- 路由和初始化可以确定性校验，领域划分本身仍由模型基于项目事实提出并由用户确认。
- 现有 Scope、Evidence、Review、规格一致性、集成与用户验收规则无需分叉。

## 未改变

不自动创建 Codex 任务，不强制每个任务使用 Worktree，不要求主 Agent 审核每次提交，不禁止跨域修改，也不把完整对话保存进 Git。

## 验证

测试覆盖初始化非覆盖、索引校验、唯一/歧义路由、按需文件加载、显式领域选择和刷新确认门禁。

## 回滚

可停止使用工作站 Skill 和命令；未初始化项目不受影响。已初始化项目可保留 `.ai/workstations/` 作为普通文档，中央上下文构建器在索引不存在时保持原行为。
