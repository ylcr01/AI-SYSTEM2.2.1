## 决定矩阵

| 机制 | 决定 | 原因 |
|---|---|---|
| Goal、Scope、ChangeSet、用户改动隔离 | 保留 | 直接防止目标漂移和越权改动 |
| 定点验证与用户验收 | 保留并收紧 | 必须显式绑定 Acceptance，不能由通用 Covers 猜测 |
| Worktree 集成与目标 HEAD 新鲜度 | 保留并加强 | 使用频率高，且首次集成存在未重验风险 |
| 规格/Decision | 按需保留 | 有实际使用，但不应进入所有任务默认上下文 |
| Review Package | 收缩 | 无显式 Review 时不写入 Task 结构 |
| Experience Candidate | 按需保留 | 当前无使用证据，不进入默认路径 |
| matching-covers / all 自动验收归因 | 删除语义 | 会制造错误证明；兼容字段只按“不绑定”处理 |
| 任意命令 Task Check、文本 input-change | 删除 | 分别扩大执行面和允许清除失败事实 |
| 常驻验证器、签名、企业审批、通用沙箱 | 不新增 | 没有与复杂度相称的真实净收益证据 |

## 后续观测

继续记录首轮验收率、返工原因、验证耗时、错误证明、状态错位和集成后回归。只有某个问题在真实任务中重复出现且当前轻量机制无法处理时，才评估新增机制；评估必须同时报告收益、成本、误报和退出条件。
