# 项目质量清单示例

`.ai/quality.json`：

```json
{
  "schemaVersion": 1,
  "contracts": [
    {
      "id": "project-web",
      "version": 1,
      "status": "active",
      "profiles": ["develop-web"],
      "roles": ["web"],
      "artifactKinds": ["code", "ui"],
      "path": "docs/architecture/web-contract.md"
    }
  ],
  "exemplars": [
    {
      "id": "project-customer-feature",
      "status": "active",
      "profiles": ["develop-web"],
      "artifactKinds": ["code", "ui"],
      "structureImpacts": ["structural"],
      "keywords": ["客户", "管理页面"],
      "read": [
        "src/views/customer/CustomerList.vue",
        "src/api/customer/index.ts"
      ],
      "contract": {"id": "project-web", "version": 1},
      "supersededBy": null
    }
  ],
  "disabledDefaults": [],
  "exceptions": []
}
```

`profiles` 是质量路由条件，不是宿主 Skill。读取旧项目清单时仍兼容 `skills` 字段，但新配置统一使用 `profiles`。

`contracts[].path`、`exemplars[].read` 与 Experience 索引中的 `read` 必须是清单所属仓库内已经存在的普通文件；目录、缺失文件、绝对路径、越界路径和符号链接逃逸都会使 Context 构建失败。存在但不是有效 JSON 对象的 `.ai/quality.json` 也会失败关闭，不能静默回退到中央默认。

显式 Quality Profile 必须已登记在中央清单或当前项目/底座的 Contract、Canonical 配置中。一次最多加载两个 Profile；命中更多时保留前两个并在 Context `warnings` 中说明截断。
