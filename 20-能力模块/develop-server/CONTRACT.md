# Server 工程 Contract

## 责任模型

### Transport / Controller
解析协议、身份上下文、参数和响应映射；不承载复杂业务和事务。

### Application Use Case
组织权限、事务、业务流程、副作用顺序和失败策略，是完整用例责任所有者。

### Domain
表达稳定业务规则和值对象，不依赖框架、数据库或网络协议。

### Repository / Adapter
隔离存储和外部系统，向应用层提供内部稳定接口。

## 强制边界
- 权限在可信身份上下文上判断，并覆盖允许与拒绝路径。
- 事务边界与业务原子性一致。
- 幂等、并发、重复请求和重试语义明确。
- 外部调用说明超时、重试、降级和错误归属。
- 数据迁移具有前后证据、兼容窗口和回滚。
- 日志不得泄露凭据和敏感数据。

## 错误
协议层统一映射错误，但保留领域/应用根因；不存在、冲突、无权限和系统失败不能混为同一结果。

## 渐进结构
简单用例不必建立完整分层；当规则稳定、多个入口复用或基础设施需要替换时再提取 Domain/Adapter。
