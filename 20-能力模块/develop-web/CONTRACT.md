# Web 工程 Contract

## 责任模型

### 页面入口
负责路由参数、页面级状态、用例组装和页面生命周期；不承载可复用业务规则。

### 业务用例 / module
拥有完整业务流程、权限分支、副作用顺序、状态转换和错误恢复。

### API
负责远端路径、请求/响应契约、认证边界和协议错误；不拥有页面状态。

### 组件
通过清晰输入、输出和事件表达责任；纯展示组件不读取业务单例或直接调用 API。

### data/config
只保存纯数据、列定义、选项和映射；不得隐藏运行时副作用。

### model
保存稳定类型、纯转换和领域值对象；不得成为任意工具兜底目录。

## 依赖方向
页面入口 → 业务用例 → API/稳定能力；展示组件依赖 model，不反向依赖页面。

## 状态与错误
状态由最接近完整流程的位置拥有。错误必须可见并保留语义，不能用空数据掩盖失败。

## 渐进结构
- 局部功能先就近实现。
- 出现稳定复用、独立变化原因或清晰业务责任时再拆分。
- 不创建无职责转发文件、空目录和未来占位层。
- 文件大小只作为判断信号，不作为自动拆分标准。

## 表单与列表
查询、重置、分页、重复提交、失败后输入保留、权限显示和刷新策略必须统一。

## 验证
根据 ChangeSet 选择类型、定点 Lint、业务分支、路由、权限、表单状态、必要 Browser 行为和控制台证据。

## 受控偏离
跨页面工作区、复杂向导或框架强约束可采用不同结构，但需保持状态所有权和依赖方向清晰。
