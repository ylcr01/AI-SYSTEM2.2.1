# Web 功能职责切片

本样板只在目标项目没有更具体架构与真实范例时参考。统一的是职责、依赖方向和渐进拆分，不是文件名或文件数量。

## 命名采用顺序

1. 先沿用目标项目和相邻功能已经稳定使用的命名。
2. 项目已绑定工程模板时，使用该模板的具体目录和文件名。
3. 只有全新项目既未绑定模板、也没有可识别的既有约定时，才使用下方缺省命名。

缺省命名不用于批量改造老项目。首个功能落地后，它和项目入口共同成为后续功能的项目事实。

```text
feature/
├─ 页面入口            路由参数、页面状态与组装
├─ API 适配            远端契约与协议错误
├─ 业务流程            副作用、权限与错误恢复（需要时）
├─ 纯模型              稳定类型与纯转换（需要时）
├─ 展示组件            明确输入、输出与事件（需要时）
└─ 行为测试            直接保护关键行为（需要时）
```

## 无项目约定时的缺省命名

全新 Vue 管理端功能默认使用：

```text
feature/
├─ index.vue             页面入口与组装
├─ data.ts               表格、表单和静态声明（需要时）
├─ api/
│  └─ index.ts           远端契约与类型（需要时）
├─ modules/              表单、弹窗和完整业务动作（需要时）
├─ components/           独立输入输出的业务组件（需要时）
├─ model.ts              无框架依赖的纯模型（需要时）
├─ <feature>.test.ts     关键行为测试（需要时）
└─ index.ts              存在功能外调用时的最小公开入口
```

非 Vue 项目只替换框架明确规定的页面入口名，例如 React 使用 `index.tsx`；Next.js、SvelteKit 等已有强路由约定时服从框架约定。其余职责仍优先使用 `data.ts`、`api/`、`modules/`、`components/` 和 `model.ts`，除非所选框架已有更明确的惯例。

每项职责可以是文件、目录或就近代码；名称服从项目现有约定。未出现的责任不创建文件，小功能可以只保留页面入口和 API 适配。

数据流：路由/用户输入 → 页面入口 → 业务流程 → API → 明确结果/错误 → 页面状态。

模型结合实际改动，从打开、查询/主操作、成功、失败、权限、重复操作和状态恢复中选择必要验证。
