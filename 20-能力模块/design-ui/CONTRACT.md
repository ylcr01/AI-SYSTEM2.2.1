# UI 与交互 Contract

## 强制边界
- 信息层级和主路径清晰。
- 覆盖默认、加载、空、成功、错误、无权限、禁用、重试和恢复状态。
- 视觉不能替代行为、权限和错误语义。
- 使用项目已有设计系统，不发明平行组件语言。
- 键盘、焦点、语义标签和对比度满足适用的可访问性要求。

## 默认职责
页面负责信息结构和用例组装；可复用组件以明确输入输出表达；业务状态不散落在纯展示组件。

## 响应式
说明桌面、窄屏和触控差异，不用简单缩放代替重新排序和交互调整。

## Browser 边界
UI 文件本身不自动要求 Browser。只有用户可观察 Browser 行为变化且更低成本 Evidence 不足时才需要。

## 验证
按用户可观察行为选择状态、响应式、键盘/读屏、设计系统、恢复和必要 Browser 证据；截图不能单独证明交互正确。
