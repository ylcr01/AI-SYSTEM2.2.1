# UI 与交互 Contract

## 设计关注
- 信息层级和主路径清晰。
- 覆盖默认、加载、空、成功、错误、无权限、禁用、重试和恢复状态。
- 视觉不能替代行为、权限和错误语义。
- 使用项目已有设计系统，不发明平行组件语言。
- 键盘、焦点、语义标签和对比度满足适用的可访问性要求。

## 默认职责
页面负责信息结构和用例组装；可复用组件以明确输入输出表达；业务状态不散落在纯展示组件。

## 响应式
说明桌面、窄屏和触控差异，不用简单缩放代替重新排序和交互调整。

## Browser 边界
默认不运行浏览器、E2E 或截图验收；只有用户在当前任务中明确要求时才执行。

## 验证
模型按实际改动选择必要的聚焦单测；状态、响应式、键盘/读屏和恢复行为可在实现中核对。用户明确要求浏览器验证时，截图也不能单独证明交互正确。
