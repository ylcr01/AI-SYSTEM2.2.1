# 大模型接入说明

AI 研发操作系统通过 `AI_RD_OS_ROOT`、根 `AGENTS.md` 和宿主自定义指令接入具备本地文件与终端能力的模型，不使用常驻 Host Adapter。

## 自动接入

1. Codex 自动读取全局与仓库 `AGENTS.md`；模型解析 `AI_RD_OS_ROOT`，并在需要时自行运行入口检查。
2. 首次安装、入口更新和项目入口初始化由模型或接入自动化完成，不要求用户复制命令、粘贴输出或维护机器配置。
3. 宿主提供可写设置接口时，模型直接更新 bootstrap；宿主没有可操作接口时，如实报告一次性能力边界，不把手工命令作为正常使用路径。
4. 具体项目需要短 `AGENTS.md` 导航时，由模型按需执行 `初始化项目 --cwd <项目路径>`。

生成器只生成用于定位根 `AGENTS.md` 的宿主 bootstrap 和必须跨仓库生效的浏览器硬边界；根 `AGENTS.md` 是中央路由与其他规则正文的唯一权威入口，项目入口模板仍由生成器维护。本文不复制生成结果。

生成的模型入口不复制预检、Worktree、正式 Task 或外部授权等项目工作流；浏览器硬边界由宿主入口统一提供，根入口只保留失载即停规则。宿主读取根 `AGENTS.md` 后获得其余当前版本规则。当前工作区干净、可用且没有已知并发写入时，普通修改由模型直接实施并展示 Git Diff；脏、占用、并发、状态不确定或用户明确要求隔离时才进入 Worktree。持续跟踪、交接、并行隔离或已授权外部写入通过显式正式 Task 使用完整门禁；高风险、结构性、规格、跨仓等语义由模型决定读取与验证，不自动创建 Task 或 Worktree。Codex managed Worktree 未落地或不可用时，模型立即创建 detached Worktree fallback，不能把内部工作树占用当作用户阻塞。项目 `AGENTS.md` 只补充项目目录、规格、命名、命令和 Contract，不复制中央事实门禁。

## Codex / ChatGPT Code

支持自定义指令的宿主直接使用“生成”结果。普通修改不调用 `准备`；只有显式正式闭环或事实预检要求隔离时，Codex 才优先选择 managed Worktree，若创建结果未落地则使用 `git worktree add --detach <新路径> <起点>` fallback。项目中的 `AGENTS.md` 可以补充项目事实，但不得降低 Git 身份、用户改动、并发、外部授权和状态真实性边界；普通任务的语义、范围与验证仍由模型结合项目事实判断。

仓库内的 `20-能力模块` 是系统自己的 Quality Profile、Contract 和 Canonical 资料层，不是 Codex 可发现 Skill。真正的 Codex Skill 必须具有独立 `SKILL.md` 包并安装到 `$CODEX_HOME/skills/`（未设置时为用户目录下 `.codex/skills/`），以宿主实际显示的可用 Skill 清单为准；不要仅凭仓库中存在同名 Markdown 文件判断它可被大模型调用。

宿主支持子代理时，仅对大输出、只读、可独立且结果可验证的探索、测试归因或汇总，才考虑低成本子代理，并要求返回结论及文件位置或命令证据。子代理可减少主会话噪声，但会增加总 Token；架构取舍、关键实现、最终 Diff 与安全/权限判断仍由主模型负责。系统不自动编排或路由模型。

## Claude Code

可在全局或项目级 `CLAUDE.md` 中要求先解析 `AI_RD_OS_ROOT` 并读取系统 `AGENTS.md`。项目规则仍不得绕过可信执行门禁。

## 使用边界

宿主必须能够读取本地文件、执行 Node.js/终端命令并访问目标 Git 工作树。普通网页聊天不会因为粘贴自定义指令而自动获得本地权限。
