# 大模型接入说明

AI 研发操作系统通过 `AI_RD_OS_ROOT`、根 `AGENTS.md` 和宿主自定义指令接入具备本地文件与终端能力的模型，不使用常驻 Host Adapter。

## 通用接入

1. 将 `AI_RD_OS_ROOT` 指向当前系统目录。
2. 运行 `node ./40-脚本/configure-model-entry.mjs 检查`。
3. 运行 `node ./40-脚本/configure-model-entry.mjs 生成`，将输出粘贴到宿主自定义指令。
4. 具体项目可按需运行 `初始化项目 --cwd <项目路径>`，生成短 `AGENTS.md` 导航。

生成器是自定义指令和项目入口内容的权威来源，本文不复制生成结果。

生成的模型入口会在编辑发生前强制路由：每个仓库写任务先进入任务专属 Worktree；Local/主工作区只读或由单一集成者串行集成。Codex managed Worktree 未落地或不可用时，模型必须立即创建 detached Worktree fallback，不能把内部工作树占用当作用户阻塞，也不能静默回到 Local。项目 `AGENTS.md` 只补充项目目录、规格、命名、命令和 Contract，不复制中央 Task/Worktree 门禁。

## Codex / ChatGPT Code

支持自定义指令的宿主直接使用“生成”结果。Codex 新写任务优先选择 managed Worktree；若创建结果未落地，使用 `git worktree add --detach <新路径> <起点>` fallback，再从该 Worktree 执行 `准备 --integration-target <目标分支>`。项目中的 `AGENTS.md` 可以补充项目事实，但不得重定义或降低中央 Worktree、Scope、Evidence、状态真实性和用户验收门禁。

仓库内的 `20-能力模块` 是系统自己的 Quality Profile、Contract 和 Canonical 资料层，不是 Codex 可发现 Skill。真正的 Codex Skill 必须具有独立 `SKILL.md` 包并安装到 `$CODEX_HOME/skills/`（未设置时为用户目录下 `.codex/skills/`），以宿主实际显示的可用 Skill 清单为准；不要仅凭仓库中存在同名 Markdown 文件判断它可被大模型调用。

宿主支持子代理时，仅对大输出、只读、可独立且结果可验证的探索、测试归因或汇总，才考虑低成本子代理，并要求返回结论及文件位置或命令证据。子代理可减少主会话噪声，但会增加总 Token；架构取舍、关键实现、最终 Diff 与安全/权限判断仍由主模型负责。系统不自动编排或路由模型。

## Claude Code

可在全局或项目级 `CLAUDE.md` 中要求先解析 `AI_RD_OS_ROOT` 并读取系统 `AGENTS.md`。项目规则仍不得绕过可信执行门禁。

## 使用边界

宿主必须能够读取本地文件、执行 Node.js/终端命令并访问目标 Git 工作树。普通网页聊天不会因为粘贴自定义指令而自动获得本地权限。
